## 四、开发过程详细步骤

### 第一阶段：项目初始化与功能开发

#### 1. 项目搭建
- 使用 Vite 创建 React 项目模板
- 配置项目基础结构：组件目录、数据目录、静态资源目录
- 设置全局暗色主题风格（背景色 `#0a0a14`，紫色强调色）

#### 2. 组件开发
按区块逐一实现各组件：

- **Navbar（导航栏）：** 固定顶部，半透明毛玻璃效果，包含站点标题和各区块锚点链接
- **Hero（首屏）：** 全屏高度的星空渐变背景，展示站名"星屑集"和副标题"收集散落在夜空中的光"
- **Gallery（图片画廊）：** 
  - 从 `data/images.js` 读取数据，自动渲染图片网格
  - 实现分类标签筛选（全部/游戏/动漫/其他）
  - 点击图片弹出大图预览（Lightbox）
  - 鼠标悬停显示标题遮罩
- **Music（音乐列表）：** 
  - 从 `data/music.js` 读取歌曲数据
  - 分类筛选功能
  - 链接到 QQ 音乐歌单
- **Footer（底部）：** 版权信息和站点说明

#### 3. 数据驱动设计
图片和音乐内容全部通过数据文件管理，修改内容只需编辑 JS 数据文件，无需改动组件代码。

### 第二阶段：部署上线

#### 4. 构建打包
- 执行 `npm run build` 生成 `dist/` 目录
- 产物包含：HTML 入口、带 hash 的 JS/CSS 文件、静态资源

#### 5. 首次部署到 Cloudflare Pages
- 将 `dist/` 目录打包为 zip 上传到 Cloudflare Pages
- 获得线上地址：https://xingxueji.pages.dev

### 第三阶段：问题排查与修复

#### 6. 白屏问题排查（核心问题）

**现象：** 访问 https://xingxueji.pages.dev 页面白屏，控制台报错，`#root`  div 为空。

**排查过程：**
1. 通过浏览器自动化工具打开网站，截图确认白屏
2. 查看控制台错误信息
3. 检查 DOM 结构，发现 `<div id="root"></div>` 是空的 — React 根本没有挂载

**根因分析：**
- `_redirects` 文件使用了**空格**分隔字段
- Cloudflare Pages 要求 `_redirects` 必须使用 **Tab 制表符**分隔
- 由于分隔符错误，所有请求（包括 JS、CSS 文件）都被重定向到 `index.html`
- JS 文件返回的是 HTML 内容，浏览器因 MIME 类型不匹配拒绝执行
- React 的 JS 无法加载 → 无法挂载 → 白屏

**修复方案：**
1. 用 `printf` 重新生成 `_redirects`，确保使用 Tab 分隔
2. 添加细粒度路由规则，在 catch-all 之前保护静态资源：

```
/assets/*	/assets/:splat	200
/images/*	/images/:splat	200
/icons.svg	/icons.svg	200
/*	/index.html	200
```

3. 重新打包上传，白屏问题解决

### 第四阶段：性能优化

#### 7. 图片优化

**操作：**
1. 备份原始图片到 `backup/` 目录
2. 使用 Sharp 库将 JPG 图片转换为 WebP 格式
3. 更新 `src/data/images.js` 中的文件引用
4. 重新构建并打包

**效果：**
| 图片 | 原始大小 | 优化后 | 压缩率 |
|------|----------|--------|--------|
| 20200324171249_spioe | 288.5 KB (JPG) | 108.1 KB (WebP) | 62.5% ↓ |
| OIP-C | 27.9 KB (JPG) | 29.2 KB (WebP) | 小图略有增大 |
| **部署包总计** | **419 KB** | **210.9 KB** | **约 50% ↓** |

## 五、遇到的问题与解决方案

| 问题 | 原因 | 解决方案 |
|------|------|----------|
| 网站白屏 | `_redirects` 用空格分隔，Cloudflare 要求 Tab | 用 `printf` + `\t` 重写，并添加细粒度路由规则 |
| `npx: command not found` | npx 不在 PATH 中 | 使用 Node.js 完整路径执行 |
| `require is not defined` | 项目使用 ES modules (`"type": "module"`) | 将脚本文件改为 `.cjs` 扩展名 |
| `git push` 失败 | 国内网络环境限制 | 改用 Node.js 调用 GitHub REST API 上传代码 |
| 图片体积大 | 原始 JPG 文件未优化 | 使用 Sharp 转换为 WebP，部署包体积减半 |
| 图片引用丢失 | 格式转换后未同步更新代码 | 更新 `images.js` 中的文件路径 |

### 沟通语言
全程使用中文沟通，技术概念用通俗语言解释。

### 典型沟通场景

**1. 描述问题（带截图）**
> 用户发送网站白屏截图，说"把总文件的练习改成Test"
> 
> → 我通过截图识别出白屏问题，先排查技术问题

**2. 下达任务指令**
> "请先备份项目中的原始图片，将网站实际使用到的图片转换为WebP格式并适当压缩，同时更新HTML、CSS和JavaScript中的图片引用。完成后检查是否存在丢失或无法加载的资源，再重新整理部署文件。更新压缩包"
> 
> → 一条完整的多步骤指令，我按顺序逐步执行

**3. 交接操作**
> "把打包文件给出路径，我来上传。"
> 
> → 用户选择自己完成某些步骤，我提供所需文件

**4. 委托自动化任务**
> "你来尝试连接到git部署吧"
> 
> → 委托我通过浏览器自动化完成 Cloudflare 配置

### 协作特点
- 用户可以在本地修改数据文件（图片、音乐），让我构建部署
- 遇到网络或权限限制时，灵活切换方案（如 API 替代 git push）
- 重要操作前会确认，避免误操作
