## 一、项目是什么

星屑集是一个**个人收藏展示网站**，展示图片、音乐、番剧和游戏收藏。

- 在线地址：`https://026924.xyz`（部署在 Cloudflare Pages）
- 技术本质：一个 **React 单页应用（SPA）**，纯前端，没有传统后端服务器
- 音乐存储：七牛云对象存储，通过 Cloudflare Pages Functions 代理访问

## 四、核心概念详解

### 4.1 React 组件化

React 的核心思想是把页面拆成一个个**组件**，每个组件管自己的 UI 和逻辑。

```
App.jsx（根组件）
├── Navbar        ← 导航栏
├── Hero          ← 首屏
├── Gallery       ← 图片区
├── Music         ← 音乐区
├── Collection    ← 收藏区
├── Guestbook     ← 留言板
├── Footer        ← 页脚
└── PlayerBar     ← 底部播放条
```

**JSX** 就是看起来像 HTML 的 JavaScript 语法：

```jsx
// 这不是 HTML，是 JSX。可以在 {} 里写 JS 表达式
<h1 className={`title${visible ? ' show' : ''}`}>{name}</h1>
```

**Props** 是父组件传给子组件的数据（只读）：

```jsx
// 父组件传 name 给子组件
<Hero name="星屑集" />

// 子组件接收
function Hero({ name }) {
  return <h1>{name}</h1>
}
```

**State** 是组件自己管理的可变数据：

```jsx
const [count, setCount] = useState(0)  // 声明状态
// count 是当前值，setCount 是修改函数
// 调用 setCount(1) 后，组件会重新渲染
```

### 4.2 组件的生命周期（useEffect）

`useEffect` 让你在组件渲染后执行副作用（请求数据、绑定事件等）：

```jsx
useEffect(() => {
  // 组件挂载后执行
  const handler = (e) => console.log(e.key)
  document.addEventListener('keydown', handler)

  // 返回的函数 = 清理（组件卸载时执行）
  return () => document.removeEventListener('keydown', handler)
}, [])  // 空数组 = 只在挂载时执行一次
```

### 4.3 Context：跨组件共享状态

问题：Music 组件点了播放，PlayerBar 要更新显示。如果靠 props 一层层传，很麻烦。

解决：用 **Context** 创建一个全局状态池，任何组件都能直接读取。

```
PlayerProvider（包裹整个应用）
  ├── Music      → 调用 playSong() 设置播放
  ├── PlayerBar  → 读取 currentSong 显示信息
  └── 其他组件   → 也能访问播放器状态
```

代码结构：

```jsx
// 1. 创建 Context
const PlayerContext = createContext(null)

// 2. Provider 提供数据
function PlayerProvider({ children }) {
  const [currentSong, setCurrentSong] = useState(null)
  const [isPlaying, setIsPlaying] = useState(false)
  // ... 更多状态和方法

  return (
    <PlayerContext.Provider value={{ currentSong, isPlaying, playSong, ... }}>
      {children}
      <audio ref={audioRef} />  {/* 全局唯一的 audio 标签 */}
    </PlayerContext.Provider>
  )
}

// 3. 子组件消费数据
function PlayerBar() {
  const { currentSong, isPlaying, togglePlay } = usePlayer()
  // 直接用，不需要 props 传递
}
```

### 4.4 自定义 Hook：useScrollReveal

Hook 就是把可复用的逻辑抽出来。`useScrollReveal` 的作用是：元素滚动到可视区域时触发出现动画。

原理：使用 **IntersectionObserver API**（浏览器原生提供的"元素可见性检测"）。

```jsx
// 使用方式
const [ref, isVisible] = useScrollReveal()

// ref 绑到 DOM 元素上，isVisible 表示是否进入视口
<section ref={ref} className={isVisible ? 'reveal' : ''}>

// IntersectionObserver 工作流程：
// 1. 监听目标元素
// 2. 元素进入视口 → 回调触发 → 设置 isVisible = true
// 3. 添加 CSS class 'reveal' → 触发 CSS 过渡动画
// 4. unobserve：只触发一次，不重复动画
```

### 4.5 HTML5 Audio API

播放器的核心就是浏览器原生的 `<audio>` 标签：

```jsx
<audio ref={audioRef} preload="metadata" />

// 通过 ref 直接操作 DOM 元素
audioRef.current.src = '/music/song.mp3'  // 设置音源
audioRef.current.load()                    // 加载
audioRef.current.play()                    // 播放
audioRef.current.pause()                   // 暂停
audioRef.current.currentTime = 30          // 跳转到 30 秒
audioRef.current.volume = 0.7              // 音量 0~1
```

**事件监听**：

```jsx
audio.addEventListener('timeupdate', () => {
  // 播放过程中持续触发（约每 250ms）
  // audio.currentTime = 当前播放进度
})

audio.addEventListener('ended', () => {
  // 播放结束 → 自动切下一首
})

audio.addEventListener('loadedmetadata', () => {
  // 元数据加载完成 → 获取总时长
  // audio.duration = 总秒数
})
```

### 4.6 Range 请求（断点续播）

浏览器播放音频不是一次性下载整个文件，而是发 **Range 请求**：

```
GET /music/song.mp3
Range: bytes=0-          ← 从头开始

GET /music/song.mp3
Range: bytes=524288-     ← 从 512KB 处继续
```

服务器返回 `206 Partial Content`，只发送请求的字节范围。这就是为什么拖动进度条能快速响应——不需要下载整个文件。

我们的中间件必须转发 `Range` 头，否则七牛云会返回完整文件，浪费流量且无法拖进度条。

## 五、数据流：从点击到出声

用户点击一首歌到听到声音，完整流程：

```
1. 用户点击 Music.jsx 中的歌曲
   ↓
2. 调用 playSong(songList, index)
   ↓  （来自 PlayerContext）
3. PlayerContext 更新状态：
   - setPlaylist(songs)
   - setCurrentIndex(index)
   - setIsPlaying(true)
   ↓
4. useEffect 检测到 currentIndex 变化：
   - audio.src = currentSong.url  （如 /music/xxx.mp3）
   - audio.load()
   - audio.play()
   ↓
5. 浏览器发出请求：GET /music/xxx.mp3
   ↓
6. 请求到达 Cloudflare 边缘节点
   ↓
7. Pages Functions（_middleware.js）拦截 /music/ 开头的请求：
   - 构造七牛 URL: http://music.026924.xyz/xxx.mp3
   - 设置 Referer: http://music.026924.xyz/  （防盗链白名单）
   - 转发 Range 头（如果有）
   - 不转发其他浏览器头（Origin, Sec-Fetch-Site 等，七牛会拒绝）
   ↓
8. 七牛云返回音频数据
   ↓
9. 中间件加上 CORS 头和缓存策略，返回给浏览器
   ↓
10. 浏览器播放音频
```

## 六、部署架构

```
用户浏览器
    │
    ▼
Cloudflare Pages（边缘节点）
    │
    ├── 静态文件（HTML/CSS/JS/图片）
    │   └── 直接从 CDN 返回
    │
    ├── /music/* 请求
    │   └── Pages Functions 拦截（_middleware.js）
    │       └── 代理到七牛云
    │           └── http://music.026924.xyz/xxx.mp3
    │
    └── 其他请求
        └── 直接返回对应文件（无客户端路由，不需要 rewrite）
```

**部署信息：**
- 平台：Cloudflare Pages（项目名 xingxueji7）
- 自定义域名：026924.xyz（CNAME 到 Cloudflare）
- 部署方式：Git 推送自动构建（`git push` → Cloudflare 自动 `npm run build` → 部署 `dist/`）
- 构建命令：`npm run build`，输出目录：`dist`

### 6.1 为什么需要代理？

七牛云设置了**防盗链**：只允许 `Referer: http://music.026924.xyz/` 的请求。

如果浏览器直接请求七牛：
- Referer 是 `https://026924.xyz` → 被拒绝（403）
- 还带有 Origin、Sec-Fetch-Site 等头 → 也被拒绝

通过中间件代理：
- 中间件在边缘服务器执行，可以自定义请求头
- 只设置七牛需要的 Referer，不带其他多余头
- 七牛认为是合法请求，返回音频

### 6.2 关于 SPA 路由

有些单页应用需要配置"所有路径都返回 index.html"（因为用了 react-router 等客户端路由）。

但星屑集**没有用客户端路由**——所有内容都在一个长页面上，靠锚点跳转（`#music`、`#gallery`）。所以不需要 `_redirects` 或 `edgeone.json` 之类的 rewrite 规则。

> `public/edgeone.json` 是之前尝试 EdgeOne 部署时留下的，对 Cloudflare Pages 没有作用。

### 6.3 缓存策略

```javascript
// 成功响应：缓存 1 年（音频文件不会变）
if (response.ok) {
  newHeaders.set('Cache-Control', 'public, max-age=31536000')
}

// 失败响应：不缓存（避免缓存 403 错误）
```

用户第二次访问同一首歌，直接从 CDN 缓存读取，不经过七牛。

      rewrite: (path) => path.replace(/^\/music/, ''),

## 十、添加歌曲流程

### 手动流程（以前）

1. 把 MP3 上传到七牛云
2. 手动编码文件名（URL encode）
3. 在 `music.js` 里手动添加一条记录
4. git commit && push 触发部署

### 自动化脚本（现在）

```bash
# 1. 把 MP3 放到 new-songs/ 目录
#    文件名格式：歌手 - 歌名.mp3

# 2. 运行脚本
node add-songs.mjs
```

脚本自动完成：
- 生成七牛上传凭证（HMAC-SHA1 签名）
- 上传 MP3 到七牛
- 解析文件名提取歌手和歌名
- 猜测分类（根据关键词）
- 更新 `music.js`
- 移动已上传文件到 `done/`

### 上传凭证原理

七牛云上传需要 **Upload Token**，生成方式：

```
1. 构造上传策略 JSON：{"scope": "bucket-name"}
2. Base64 编码 → encodedPutPolicy
3. 用 SecretKey 对 encodedPutPolicy 做 HMAC-SHA1 签名 → encodedSign
4. Token = AccessKey:encodedSign:encodedPutPolicy
```

上传时带上这个 Token，七牛验证签名合法就接受文件。

## 十一、添加图片流程

### 图片存储方式

图片直接存在 GitHub 仓库里（`public/images/`），跟代码一起部署到 Cloudflare CDN。

与音乐不同，图片不需要外部存储，因为：
- 图片体积小（目前 5 张共 500KB）
- GitHub 仓库限制 1GB，图片离上限还远
- Cloudflare CDN 自带全球加速

### 手动添加

1. 把图片放到 `public/images/`
2. 在 `src/data/images.js` 加一条记录
3. git push

### 自动化脚本

```bash
# 1. 把图片放到 new-images/ 目录
#    文件名格式：分类-标题.webp（如：游戏-明日方舟.webp）

# 2. 运行脚本
node add-images.mjs
```

脚本自动完成：
- 复制图片到 `public/images/`
- 解析文件名猜测分类和标题
- 更新 `images.js`
- 移动已处理文件到 `done/`

### 什么时候需要迁移到七牛

如果图片总量超过 100MB（几百张高清图），可以考虑迁移到七牛云，和音乐一样通过代理访问。目前 500KB 完全不需要。

## 十二、关键踩坑记录

### 11.1 七牛防盗链 403

**问题**：浏览器直接请求七牛返回 403。
**原因**：七牛防盗链白名单只允许 `Referer: http://music.026924.xyz/`。
**解决**：通过 Pages Functions 代理，在服务器端设置正确的 Referer。

### 11.2 浏览器头导致 403

**问题**：代理转发后仍然 403。
**原因**：浏览器发的请求带有 `Origin`、`Sec-Fetch-Site` 等头，七牛检测到不一致会拒绝。
**解决**：中间件只转发 `Referer` 和 `Range`，不转发其他头。

### 11.3 缓存了 403 错误

**问题**：修好后仍然播不了。
**原因**：之前的 403 响应被设置了 `Cache-Control: max-age=31536000`（缓存 1 年）。
**解决**：只对 200 成功响应设置缓存头。

### 11.4 HEAD 请求返回 403

**现象**：`curl -sI` 测试七牛返回 403，但浏览器能正常播放。
**原因**：七牛对 HEAD 请求的防盗链校验更严格，GET 请求正常。
**结论**：不影响实际使用，浏览器用的是 GET/Range。

## 十四、术语速查

| 术语 | 含义 |
|------|------|
| SPA | 单页应用，只有一个 HTML，路由由前端 JS 处理 |
| CDN | 内容分发网络，在全球节点缓存静态文件 |
| CORS | 跨域资源共享，浏览器安全策略 |
| Referer | HTTP 头，告诉服务器"我从哪个页面来的" |
| Range 请求 | 只请求文件的一部分，用于音视频分段加载 |
| Edge Function | 在 CDN 边缘节点运行的轻量函数 |
| HMAC-SHA1 | 一种签名算法，用于验证请求合法性 |
| HMR | 热模块替换，改代码浏览器自动更新 |
| Lightbox | 图片全屏查看器 |
| IntersectionObserver | 浏览器 API，检测元素是否进入视口 |
