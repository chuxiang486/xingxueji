# 曲库后台

在本地使用 Node.js 22.13 或更新版本。项目根目录的 `.env.local` 中设置 `ADMIN_TOKEN=随机长密钥`，运行 `npm run dev`，打开终端显示的站点地址并进入 `/admin/`。密钥框中只粘贴等号后面的值。退出或刷新管理页后需再次输入密钥。

首次使用会把 263 首歌曲导入本地 SQLite 文件 `.wrangler/catalog.sqlite`。在管理页选择歌曲后可修改歌名、歌手、分类和音频地址。删除操作只移除曲库记录。新增歌曲时填入已有音频文件的地址。保存后刷新首页查看结果。

## 发布到 Cloudflare Pages

同一个管理页也支持图库、壁纸、追番和游戏。登录后用“管理栏目”切换。图库和壁纸可填写已有图片的 HTTPS 地址或站内路径。现有图片改名会保留缩略图，更换原图地址后会直接显示新图。删除只移除展示条目。线上数据库还需要执行增量迁移 `migrations/0002_content.sql`，已初始化曲库的数据库只执行这份增量迁移。示例命令为 `npx wrangler d1 execute xingxueji-catalog --remote --file migrations/0002_content.sql`。

1. 创建专用于曲库的 D1 数据库（例如 `xingxueji-catalog`）。从项目根目录对新库执行 `npx wrangler d1 execute xingxueji-catalog --remote --file migrations/0001_songs.sql`。这一步导入随仓库提供的初始曲库。请勿对已有数据的库重复执行。
2. 在对应 Pages 项目的生产环境添加 D1 绑定，变量名为 `DB`，选择刚初始化的数据库。
3. 在同一环境添加加密 Secret `ADMIN_TOKEN`，使用独立生成的随机长密钥。
4. 重新部署项目，打开站点的 `/admin/`。本地测试库和线上数据库相互独立。上线后通过线上后台维护歌曲，后续发布代码无需再次初始化数据库。

[Cloudflare Pages 数据库绑定文档](https://developers.cloudflare.com/pages/functions/bindings/#d1-databases)
